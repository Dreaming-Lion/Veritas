## 2. 응답 성능
### 2-1. v1 대 v2 (기사 40건, 동일 기사)
| | 평균 | 중앙값 | P95 |
|---|---|---|---|
| v1 캐시 미스 | 44.7s | 43.5s | 65.3s |
| v1 캐시 히트 | 12ms | 11ms | 15ms |
| v2 원본 | 35.1s | 39.1s | 58.7s |
- NLI 추론이 v2 총 시간의 **99.6%**, v1의 91.5%. Qdrant 검색은 평균 0.05s(P95 0.10s).
- v2 원본의 추천 0건(5건)은 NLI를 거의 돌리지 않아 평균을 낮춥니다. 추천이 나온 35건만 보면 v2 평균 40.1s로 v1 캐시 미스와 큰 차이가 없습니다. **v2 원본의 속도 우위는 주장하기 어렵습니다.**

### 2-2. NLI 후보 수 변형 (동일 40건)
| 변형 | 평균 | P95 | 후보 80건 결과와 Top-5 겹침 |
|---|---|---|---|
| 배치 추론만 (80건) | 26.7s | 40.3s | 기준 |
| 후보 20건, fp32 | 7.4s | 11.2s | **100%** |
| 후보 20건, int8 | 6.2s | 9.1s | 56% |
| 후보 10건, int8 | 3.0s | 4.2s | 59% |
- 후보 80→20건으로 줄여도 Top-5가 35건 모두 같았습니다. int8은 순위를 크게 바꿔 채택하지 않았습니다.

### 2-3. 최종 v2+ (임베딩 혼합, 후보 20건, 배치, fp32)
- 개발용 15건: 평균 8.5s / P95 9.3s, 독립 15건: 평균 9.4s / P95 10.8s. 추천 0건 없음.
- 필터 수정만 적용(동일 15건): 평균 31.8s, 추천 0건 2건 그대로 → 추천 누락의 주원인은 필터 버그가 아니라 폴백 로직(시간 창 확대 폴백으로 해결).

## 3. 추천 품질 (예비 수치 — LLM 판정)
기준 기사별 Top-5를 **"같은 이슈·사건을 다루는가"**로 판정했습니다. 사람이 아닌 Claude가 제목과 요약만 보고 판정했고 **관점 차이는 판정하지 못했습니다.** `label_sheet.csv`(개발 15건), `label_sheet_heldout.csv`(독립 15건)의 `human_label` 열에 팀이 검수할 수 있습니다.
적합 = 같은 이슈 + 반대 성향 언론사. "정답 가능" = 어느 시스템이든 적합 추천을 1건 이상 찾아낸 기준 기사(나머지는 코퍼스에 해당 기사가 없었음).

| | 개발용 15건 (설정 선택에 사용) | 독립 15건 (미사용) | 합계 30건 | 합계, 정답 가능 20건 |
|---|---|---|---|---|
| v1 | 28/75 (37%) | **47/75 (63%)** | **75/150 (50%)** | **75/100 (75%)** |
| v2 원본 | 19/65 (29%) | 30/70 (43%) | 49/135 (36%) | 49/95 (52%) |
| v2+ (최종) | 29/75 (39%) | 42/75 (56%) | 71/150 (47%) | 71/100 (71%) |

- 개발용 15건에서는 v2+가 v1과 비슷하거나 약간 높지만, **독립 15건에서는 v1이 7%p 앞섭니다.** 개발용 수치는 설정을 고르는 데 쓴 표본이라 과대평가입니다. 결론은 "v2+는 v1에 근접하지만 아직 못 미친다"입니다.
- 개선 과정(개발용): 요약 기반 TF-IDF의 NLI 우선 정렬 규칙 제거(유사도순)로 54%→74%, 신경망 임베딩(multilingual-e5-small) + 후보 집합 TF-IDF 혼합으로 소폭 추가 개선.
- **효과 없었던 시도(기록):** 본문 우선 인덱싱, 후보 집합 TF-IDF 단독 혼합, 임베딩 단독, 질의만 본문 사용(합계 65%), 질의·문서 모두 본문 사용(합계 69%) — 모두 최종(71%)보다 낮아 반영하지 않았습니다. 요약이 짧아 질의가 부실할 것이라는 가설은 틀렸습니다.
- 한계: 기준 기사 30건·판정자 1명(LLM). 다수가 같은 대형 이슈(조작기소 특검법)에 몰려 있어 일반화에 한계가 있습니다. 같은 표본으로 계속 설정을 고르면 과대평가가 커지므로 여기서 멈췄습니다.

## 4. 운영 비용
| | 값 |
|---|---|
| v1식 사전 계산 (기사 1건당) | 약 44.7s × 582건 ≈ **7.2시간** (파라미터 조합 1개 기준 추정) |
| v2 원본: 180분마다 TF-IDF 전체 재구축 | 582건 약 1.4s이지만, 재구축 중 컬렉션이 비고 새 기사는 최대 3시간 뒤 반영 |
| **v2+ 최초 전체 인덱싱** | 582건 177s (임베딩 + 요약 포함, 기사당 약 0.3s) |
| **v2+ 증분 인덱싱** | 새 기사 20건 3.7s (기사당 **0.18s**), 1건 **0.25s**, 새 기사 없음 0.15s |
| v2+ 오래된 기사 삭제 (30일 초과) | 0.06s |
| v2+ 클릭 1회 | 약 9s |
- v2+는 사전 계산 없이 클릭 시 약 9s만 씁니다. 사전 계산 비용(7.2시간)과 같아지려면 한 주기에 약 2,900회 클릭이 필요합니다(추정).
- 증분 인덱싱은 신경망 임베딩이라 가능합니다. TF-IDF는 새 기사마다 어휘·가중치가 바뀌어 증분이 안 됩니다.
- 통합 코드 검증: 저장소에 통합한 `recommend_v2plus.py`의 추천 결과가 벤치마크 기사 5건에서 Top-5 완전 일치.
